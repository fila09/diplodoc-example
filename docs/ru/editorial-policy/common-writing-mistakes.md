# Типичные ошибки технического текста

В технической документации важно не только точно описать работу системы, но и сделать текст понятным пользователю. Сложные формулировки, канцелярские обороты и лишние слова затрудняют чтение и могут скрывать смысл инструкции.

В статье рассмотрены распространенные языковые ошибки технической документации и способы их исправления.

## 1. Канцелярские конструкции

Канцелярит — это слова и обороты, характерные для официально-делового стиля, которые без необходимости усложняют текст.

Один из распространенных примеров — сочетание глаголов «выполнить», «произвести», «осуществить» с существительным, обозначающим действие.

Такие конструкции часто можно заменить одним глаголом.

| Неудачная формулировка | Лучше |
|---|---|
| Выполнить настройку | Настроить |
| Произвести установку | Установить |
| Осуществить запуск | Запустить |
| Выполнить создание пользователя | Создать пользователя |
| Выполнить удаление записи | Удалить запись |
| Осуществлять мониторинг | Отслеживать состояние |
| Произвести проверку | Проверить |
| Выполнить подключение | Подключить |
| Произвести замену сертификата | Заменить сертификат |
| Выполнить перезапуск сервиса | Перезапустить сервис |

**Почему лучше:** глагол сразу обозначает необходимое действие. Пользователю не приходится мысленно преобразовывать сложную конструкцию в простую команду.

Например:

**Неудачно:**

> Для выполнения настройки подключения необходимо произвести изменение параметров конфигурации.

**Лучше:**

> Чтобы настроить подключение, измените параметры конфигурации.

Второй вариант короче, а требуемое действие выражено непосредственно.

{% note info %}

Не все сочетания глагола с существительным являются ошибками. Например, «выполнить резервное копирование» может быть уместно, особенно если «Резервное копирование» — название операции в интерфейсе продукта.

{% endnote %}

## 2. Избыточные слова и обороты

Некоторые слова не добавляют полезной информации, но делают предложение длиннее и сложнее.

| Нежелательно без необходимости | Возможная замена |
|---|---|
| Данный | Этот или название объекта |
| Соответствующий | Конкретное название объекта |
| Вышеуказанный | Указанный или название объекта |
| Нижеприведенный | Приведенный, следующий |
| В рамках | Для, при, во время |
| С целью | Чтобы, для |
| Посредством | Через, с помощью |
| Путем использования | Используя, с помощью |
| Имеет возможность | Может |
| Осуществляется | Выполняется, происходит или конструкция с конкретным исполнителем |
| Производится | Выполняется или конструкция с глаголом действия |

Замены в таблице зависят от контекста. Необходимо сохранять исходный смысл предложения.

### Пример 1. Избыточное слово

**Неудачно:**

> Для изменения данного параметра необходимо открыть соответствующее окно.

**Лучше:**

> Чтобы изменить параметр, откройте окно настроек.

В исправленном варианте убраны лишние слова и уточнено назначение окна.

### Пример 2. Сложная конструкция

**Неудачно:**

> С целью обеспечения корректной работы системы необходимо произвести проверку доступности сервера.

**Лучше:**

> Чтобы система работала корректно, проверьте доступность сервера.

Во втором варианте цель действия сохраняется, но инструкция становится короче.

### Пример 3. Неопределенное действие

**Неудачно:**

> После сохранения настроек производится перезапуск сервиса.

Такое предложение не позволяет однозначно определить, кто перезапускает сервис: пользователь или система.

В зависимости от фактического поведения продукта текст можно написать по-разному.

**Если действие выполняет пользователь:**

> После сохранения настроек перезапустите сервис.

**Если действие выполняет система:**

> После сохранения настроек система автоматически перезапускает сервис.

{% note tip %}

Если в предложении непонятно, кто выполняет действие, попробуйте указать исполнителя и использовать глагол в активном залоге.

{% endnote %}

## 3. Отглагольные существительные

Отглагольные существительные образованы от глаголов и обозначают действия или процессы: «создание», «удаление», «настройка», «выполнение», «изменение».

Они широко используются в технической документации и сами по себе не являются ошибкой.

Проблемы возникают, когда вместо прямого указания на действие используется громоздкая конструкция.

| Неудачная конструкция | Лучше |
|---|---|
| Выполните создание пользователя | Создайте пользователя |
| Произведите удаление записи | Удалите запись |
| Осуществите настройку подключения | Настройте подключение |
| Выполните проверку | Проверьте |
| Произведите изменение конфигурации | Измените конфигурацию |
| Осуществите запуск приложения | Запустите приложение |

### Когда отглагольные существительные уместны

Такие существительные можно использовать в заголовках, названиях операций, описаниях процессов и терминах.

Например:

- Создание пользователя
- Удаление сертификата
- Настройка кластера

В этих случаях существительное помогает обозначить тему раздела или название операции.

Но в пошаговой инструкции обычно лучше использовать глаголы в повелительном наклонении.

**Заголовок:**

> Создание пользователя

**Шаг инструкции:**

> Создайте пользователя.

Такой подход позволяет сохранить привычные названия разделов и одновременно сделать инструкции понятными.

## 4. Как проверить текст

При редактировании технической статьи обратите внимание на следующие признаки:

1. В предложении есть сочетания «выполнить настройку», «произвести проверку», «осуществить запуск» и подобные конструкции.
2. Встречаются слова «данный», «соответствующий», «вышеуказанный» без очевидной необходимости.
3. Простое действие описано несколькими словами вместо одного глагола.
4. Из предложения непонятно, кто выполняет действие.
5. После сокращения формулировки смысл и точность инструкции сохраняются.

Не заменяйте слова автоматически. Убедитесь, что исправленный текст правильно передает поведение системы и не противоречит терминологии продукта.

**Основной принцип:** используйте максимально простую формулировку, которая точно передает необходимую информацию.
